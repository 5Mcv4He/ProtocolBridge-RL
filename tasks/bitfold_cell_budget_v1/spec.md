# 位计数的功能保持与结构预算

初始实现能够正确计算8位输入中1的个数，也能综合，但在本任务固定流程中产生33个映射单元，超过22个的预算。请改写实现，保持全部输入下的组合功能，同时满足明确的结构上限。这是固定教学库与映射流程下的工程结构任务，不是实际工艺面积、时序或功耗优化。

## 功能与可修改范围

仅修改 `bitfold.sv`，唯一模块 `bitfold(input logic [7:0] data, output logic [3:0] result)`。组合逻辑，无时钟、复位或状态。所有二态data值0–255都合法，result必须等于其中1的个数，范围0–8。例：00→0，81→2，FF→8；不能截掉最高输入位或把8截断为0。无输入历史依赖。

允许常量、组合算术、位操作、组合过程与静态有界循环。要求自包含可综合RTL。禁止宏、include、外部模块、文件／层次访问、系统任务、initial、延迟、外部约束、工具脚本或评分器修改。不能删除必要功能来降低指标。

## 成功条件与固定测量

全部条件同时满足：

1. 独立整数模型对全部256个输入、不同顺序检查通过。
2. 与独立可信参考的Formality比较完整通过，不存在未证明、缺失或黑盒比较点。
3. Design Compiler完整综合，寄存器数和未映射实例数均为0。
4. 候选与自己的综合网表完整等价；这一项只证明变换一致，不替代第二项。
5. 固定综合脚本中 `sizeof_collection [get_cells -hierarchical *]` 的结果不超过22。该值计映射实例，不是门等效面积或真实芯片面积。

使用DC O-2018.06-SP1及固定教学库、10单位虚拟时钟、输入／输出延迟0.1、medium映射。可信侧冻结脚本和库身份，不接受候选提供的约束。脚本计数在本任务单模块组合设计上使用；不同环境或库不能直接继承该预算的准入证据。

候选通过完整功能与变换检查后，公开test返回 `mapped_cell_count`、`limit` 和 `functional_checks_passed`。这是本次候选的实际测量，旧版本计数不能证明新版本满足条件。如果功能或执行过程失败，不提供看似有效的优化指标。

功能与全部结构条件通过reward=1；确认的功能／编译／结构条件错误为0。无效提交、库不匹配、工具故障、不完整证明或缺失测量为null，不作为模型设计失败。
