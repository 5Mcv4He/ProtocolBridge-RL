# 实现深度 2 的 FIFO 事务检查器

你的交付物是检查器，不是 FIFO 本身。每周期收到入队／退休事件，检查退休身份是否与最早未退休的请求一致，同时识别容量与复位违例。可信侧会评价你的误报和漏报；候选不能修改验收规则。

## 固定接口与行为

唯一模块 fifo_checker，按顺序命名端口 clk,rst_n,push,pop,push_id,pop_id,error。前六项输入，error 输出；两个 id 为 8 位无符号，其余为 1 位。无参数，clk 上升沿采样，低有效同步复位。

rst_n=0 优先于所有事件，清空待退休身份、数量及 error。非复位时：push 表示提出入队 push_id，pop 表示提出退休 pop_id。最多 2 个未退休请求。每个 pop 必须匹配该沿之前队列的最早身份；重复 ID 合法，不要求全局唯一。

以下任一情况使该沿之后 error=1：空队列 pop（即使同周期 push）；满队列 push 且无 pop；非空队列 pop_id 与旧队首不同。发生错误后 error 必须持续为 1，忽略其余事件，直到复位。

没有错误时，先退休旧队首，再将新身份入队。同周期 push/pop 在非空队列合法，包括满队列：数量不变，pop 对应旧身份，不能比较新 push_id。只有 push 时数量加一，只有 pop 时减一，无事件时保持。error 在所有合法周期必须为 0。

例如队列为 [7]、同周期 push_id=9 且 pop_id=7，结果为 [9] 且不报错。若队列为空，push_id=9 且 pop_id=9 仍是非法空退休，不能当作直通。复位之后旧身份不再存在。

## 交付、范围与判据

只修改 checker.sv，保持上述接口，提交自包含可综合 RTL。禁止 include、宏、外部实例、层次引用、系统任务、initial、延迟、文件访问与可执行测试台。输入为二态同步事件，不要求 AXI/APB 协议检查、异步时钟或 PPA 优化。

可信事件模型与候选分别处理同一组事件。VCS 逐周期核对 error，不以最终报错数量评分。合法序列、重复身份、同周期交换、多轮存储使用、复位取消以及明确非法事件都必须检查；无条件通过与无条件拒绝均不能获得奖励。公开、终局和独立保留使用分别冻结的身份输入。

有效候选行为错误或编译错误为 Reward=0；完整必要检查通过为 1；无效交付、工具故障、超时或不完整执行为 null，并分别归因。有限验证不能证明对全部任意序列完备。工具预算由试次配置冻结。
