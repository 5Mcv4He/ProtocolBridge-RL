# Active-VIP UVM acceptance evidence

This directory contains reviewed results from the executed single-task baseline,
not raw vendor logs or a claim of exhaustive correctness.

- [Control summary](controls-summary.json): reference and six faulty RTL implementations.
- [Agent final reward](agent/result.json): 128 checked transactions, reward 1.0.
- [Final submitted source](agent/final.sv): exact code evaluated.
- [Compact tool trace](agent/trace.json): actions and feedback; repeated file/code bodies use hashes.
- [Trace provenance](agent/trace-provenance.json): hash of the full privately retained trace.
- [Frozen manifest](agent/freeze.json): exact task/evaluator/environment/fixture file hashes.

Each run subdirectory contains structured results, original project-generated
`PB2_` event lines, and hashes of raw evidence. Protocol-error counts are derived
from the private simulator log; proprietary log bodies are not published.

Controls compile a bank of separate RTL modules, then run a fresh simulation for
each selected implementation. The bank is generated by `environment.validate`
from the published fixtures and is omitted as redundant output. `source_sha256`
in control results identifies that generated bank; `fixture_sha256` identifies
the selected original RTL, and `compiled_bank_selection` records its index.

Agent compilation is separate from the control bank. Final grading used the same
compiled inputs as its public test, copied into a different simulation directory
and executed with separate final vectors. See [the evaluation report](../../mvp-evaluation-report.md)
and [reproduction instructions](../../docs/mvp-running.md).

Full Harness responses, intermediate candidates, compiler products, raw logs and
superseded experiments remain local. Important unsuccessful bring-up results are
summarized in [bring-up evidence](../vip-bringup.json) and the
[Harness format failure](../harness-format-failure/README.md).
