# 为协议桥构造有效测试：地址、字节写与数据返回

这次交付物是测试激励，不是 RTL。可信运行器将你的同一份事务表用于合法桥和固定错误桥，再由独立 UVM Scoreboard 判断事务是否正确。你的任务是使合法设计正常通过，同时让与本任务要求相关的功能缺陷实际暴露。不能编辑运行器、检查器、DUT 或参考模型。

## 被测对象及判据

桥接单时钟 32 位 AXI4-Lite 与 APB4。一次只执行一笔请求，AW 地址与 W 数据可错开到达，必须配对后执行一次 APB 写。读地址直接转换为 APB 读。地址和数据不能改变，WSTRB 四个位对应四个字节，未使能字节不能被写。APB 必须先 Setup 再 Access，等待 PREADY 才完成。PSLVERR 映射为 AXI SLVERR，否则 OKAY；错误写不改变目标内存。读回准确数据；未写地址有可信初始化模式，不需要你预测它。AXI 响应受背压时保持 valid、数据和响应，直到消费。

只支持 4 字节对齐地址、单笔顺序请求、32 位数据。每行事务执行并消费完响应后才开始下一行；写的 AW/W 可相互延迟。此任务不要求事务中复位、并发读写、Burst、ID 或超时恢复。

## 唯一交付文件与字段

`stimulus.json` 必须只含 `transactions` 字段，值为 1–32 行数组。每行恰好九个 JSON 整数，依次为：

`[write, address, data, strobe, aw_delay, w_delay, wait, stall, error]`

- write 为 1（写）或 0（读）。address 为 0–4294967295 内的 4 字节对齐地址，data 为同范围无符号整数，strobe 为 0–15。
- aw_delay 与 w_delay 为 0–16，从这笔写启动时起算的通道 offer 延迟（时钟周期）。读行必须把这两项与 strobe 置 0；读行 data 被忽略。
- wait 为 0–16，指定 APB Access 中 PREADY 尚未完成的等待周期。
- stall 为 0–16，响应出现后额外阻塞消费的周期。驱动采用反应式 ready，此外存在一个 ready 反应周期；0 不表示 ready 预先保持为高。
- error 为 0 或 1，指定本笔目标 APB 响应是否报错。

例如 `{"transactions":[[1,256,305419896,15,0,0,2,3,0],[0,256,0,0,0,0,0,0,0]]}` 在地址 256 写入 0x12345678，再读回。请自行构造满足本任务目标的测试，此例不保证检出所需错误。

## 本任务的工程目标

构造能检出地址映射、写字节使能和读取数据错误的测试。考虑重复地址、不同数据及独立字节写后读回；只用全字写不一定检查到字节使能。

所有阶段都要求至少有实际完成的读和写。
公开工具只反馈整体结果及受控类别，不暴露错误 RTL 或私有结果。公开调试、终局和独立保留评估使用不同固定错误实现；同一份测试必须对合法实现有效。独立评估不回流给求解过程，也不作为终局 Reward。

## 奖励及限制

解析或范围不合法、空计划为无效提交（Reward=null）。合法输入如果可信正对照不能正常完成，则归为环境或验证问题（null），不会算成检出错误。有效活动不足、必要错误未检出为 Reward=0。必须在合法设计通过的前提下，对本阶段所有必要错误获得明确的事务功能或协议时序拒绝，才能 Reward=1。编译失败、无条件报错、超时、进程退出和错误数量本身不能算检出缺陷。

执行预算由运行配置声明。最多 32 行且各等待量有上界；不接受可执行脚本、SystemVerilog、检查断言或额外 JSON 字段。固定错误库提供的是有限的缺陷区分能力，不证明你的测试对所有可能缺陷完备。
