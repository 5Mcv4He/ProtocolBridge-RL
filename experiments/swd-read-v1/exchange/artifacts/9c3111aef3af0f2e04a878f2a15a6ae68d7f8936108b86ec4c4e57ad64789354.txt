# SWD 有限读响应：接收请求、交出数据线、完整归还

芯片调试接口 SWD 使用一根双向数据线。主机发请求后，目标需要等待方向切换，再发送响应与数据，最后释放数据线。你要实现这一局部读响应模块；它是 **SWD 传输层切片，不是完整的 Debug Port、CPU 调试器或寄存器系统**。

## 输入与交付

只修改 `target.sv`，唯一自包含模块 `swd_read`。端口顺序固定：

| 端口 | 方向／位宽 | 作用 |
| --- | --- | --- |
| clk、rst_n | 输入，各1位 | 100 MHz 系统时钟，低有效同步复位 |
| swclk、swdio | 输入，各1位 | 主机的1 MHz SWD时钟、双向线上解析后的电平 |
| read_value | 输入，32位 | 本次返回的透明数据载荷，不解释DPIDR架构字段 |
| dout、oe | 输出，各1位 | 数据值及驱动使能；可信外围以oe决定是否驱动SWDIO |

不在候选内实现三态管脚。所有采样输入为二态，SWCLK占空比50%，它的上升沿与clk不重合，每半周期含50个系统时钟。候选用clk观察SWCLK边沿。首次请求前至少两拍复位；复位仅在事务间发生，必须清除解析状态并令oe=0。oe=0时dout无约束。

## 唯一支持的事务

主机先发送至少50个1，再发送至少两个0，完成线复位。主机随后只发送合法DP读请求：APnDP=0、RnW=1、地址A[3:2]=00。八个请求位依次为 `1,0,1,0,0,1,0,1`，即LSB-first的A5。请求位在SWCLK上升沿前稳定，由目标在该边沿接收；最后一位为Park。

下表用 **Park上升沿记为0**，给出后续上升沿的目标行为。每项应在对应上升沿后的100 ns内生效，然后保持到下一上升沿；不能在其他时段修改有效输出或oe。

| 相对上升沿 | 目标行为 |
| --- | --- |
| 请求及0 | oe=0；接受完整请求，捕获read_value |
| 1 | 一个完整方向切换周期，oe=0 |
| 2、3、4 | oe=1，依次发送ACK的1、0、0（OK） |
| 5–36 | oe=1，依次发送捕获载荷的bit0–bit31 |
| 37 | oe=1，发送32个数据位的异或，即偶校验位 |
| 38 | oe=0，归还数据线；不得继续驱动 |

read_value从请求开始前稳定到Park后100 ns，随后可以改变。必须返回在该请求中捕获的32位值，不能在发送过程中重新读取外部载荷。主机在后续下降沿观察目标输出。校验位只涵盖数据，不涵盖ACK或请求。

完成后可以直接再次请求，不要求新的物理复位或线复位。连续请求的数据可不同；事务之间插入线复位或物理复位也合法。空闲时、线复位时、主机发请求时以及两个方向切换周期中，目标均不得驱动总线。

## 明确不支持的行为

不测试AP访问、DP写、其他地址、WAIT/FAULT、无效请求、错误请求校验、可变方向切换周期、JTAG／休眠切换、多目标寻址、暂停中的事务复位或线复位、完整DP寄存器语义、模拟电气或亚稳态性质。不能把这个有限模块的通过称为完整ADIv5兼容性证明。位级规则依据Arm IHI0031D B4.2/B4.3；上表与固定时钟条件是本任务的明确接口约束。

## 工具与独立判定

Agent可读规格和当前文件、修改当前文件、调用公开检查、提交；预算由对应实验条件给出。禁止文件／层次访问、宏、include、外部模块、initial、延迟、系统任务、测试台及修改评分器。

可信侧使用工业SWD主机产生真实协议请求，同时以独立引脚解码器核对请求、驱动方向、ACK、数据、奇偶校验和完成数量，并核对VIP接收的实际数据。公共检查结果绑定当前源码；提交冻结文件并停止求解。终局与保留评估独立执行，不返回模型继续修复。完整通过reward=1；确认的数据／时序错误或编译错误为0；无效提交、基础设施问题和未完整执行为null。
