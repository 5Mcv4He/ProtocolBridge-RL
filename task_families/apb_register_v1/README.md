# 把寄存器语义变成有限 APB 任务

协议桥负责把请求送到目标，目标设备还需要决定请求怎样改变状态。例如，同样写入 `1`，普通寄存器会保存它，W1C（写一清零）状态位却会清除它。工业 VIP 可以检查 APB 总线时序，但通用存储预测不能替代这些设备语义。本任务族研究如何在已限定的寄存器域中，同时生产设计材料与独立功能检查。

**当前两份生成契约已完成真实实例功能对照和证据审计，尚未取得 Agent 运行准入，也没有模型试次。** [独立角色探针](../../verification_components/apb_master_v1/README.md)先验证主动 APB 激励，再分别验收设备语义。材料生成不会自动授予准入，功能通过也不能代替隔离运行接口验收。

## 契约改变了什么工程要求

对象是单时钟、32-bit APB4 从设备，有两个至四个精确字地址。每个地址独立声明复位值、可写位掩码和访问方式：普通读写、只读或 W1C。接口支持全部四位字节使能，所有访问等待固定的零至三个 Access 时钟边沿。复位仅在总线空闲时施加；事务中复位不属于第一版契约。

未映射地址和非对齐地址返回错误，读值为零，不能改变任意寄存器。只读写入则正常完成但不改变状态。两者的响应含义不同，不能用一种默认错误策略代替。等待规则也适用于错误响应。

例如，普通寄存器原值 `0x12345678`，写值 `0xa1b2c3d4`，字节使能为 `0b0101`，全部位可写时结果应为 `0x12b256d4`。若还有位写掩码，则必须同时满足字节和位两个条件。将这个对象改成 W1C 会改变更新函数、初始见证、检查与负例适用性，不只是改一个参数标签。

合法生成域有额外的验证前提：地址和复位字可区分；至少一个读写寄存器有跨字节的可写见证；W1C 必须有复位后可清除的位。这些限制属于当前验证组件的适用域，不表示其他寄存器设计不可实现。

## 从新契约生产材料

```json
{
  "task_id": "apb_register_example_v1",
  "wait_cycles": 2,
  "registers": [
    {"address": 12, "reset": 305419896, "write_mask": 4294967295, "access": "rw"},
    {"address": 32, "reset": 65535, "write_mask": 4294967295, "access": "w1c"}
  ]
}
```

将契约存为 `contract.json` 后，在项目 checkout 中执行：

```bash
python3 -m task_families.apb_register_v1.generate contract.json candidate
```

输出包含 Spec、接口模板、两种合法实现结构、适用负例、验证义务、语义锚点、场景和来源清单。它明确标记为尚未工业准入。契约解析、实例生产与评分分别由 [contract.py](contract.py)、[generate.py](generate.py) 和 [campaign.py](campaign.py) 实现。

## 判据怎样独立于候选

可信检查器从接口上记录 Setup、Access 和实际完成，独立维护每个寄存器的状态；读回必须与它接受的写入、字节使能和位掩码一致。场景覆盖所有字节使能，并在修改后读取其他目标，检查地址别名和状态串扰。W1C 场景先恢复复位状态，避免所有位已经清零时测试失去区分力。

Python 的逐字节语义锚点与 SystemVerilog 的掩码状态模型分别实现，典型更新还有固定值测试。两种合法 RTL 采用不同更新表达。表达式不同仍可能共享错误理解，因此真实合法对照、功能负例及独立语义审查都是后续工业准入的必要条件。

评分检查实际传输数、复位数、等待边沿和必要覆盖；缺少完整执行证据时不能给成功奖励。功能或时序违例、候选编译失败、无效提交及可信环境故障分别分类。第一版每次独立编译，不声称已有安全的跨候选构建复用。

本地评分器仅供可信控制器在已配置的 EDA 环境中调用，尚未接入隔离 Agent 会话。候选不能选择检查器或运行命令。候选与工具配置仍需由完整运行环境隔离，源码限制本身不构成完整操作系统安全保证。

新增[实例对照执行器](../../environment/register_instance_controls.py)逐一编译合法和适用错误实现，并在调用前核对完整材料依赖集合；现已在两份实例上完成实际控制银行和[证据一致性审计](../../scripts/audit_register_controls.py)。清单缺项、候选编译失败或仿真超时不能充当功能负例被检出的证据。

进一步核查：[引脚与状态检查](tb.sv.in)、[激励与独立锚点](verification.py)、[失败关闭的结果分类](results.py)、[当前静态测试](../../tests/test_apb_register_contract.py)。当前不得据此推断任何具体实例已经获得可信终局奖励。


## 两份新契约实际通过了什么

| 契约 | 新增语义与条件 | 两种合法结构各自的活动 | 适用功能负例 | 整项验收耗时 |
| --- | --- | --- | ---: | ---: |
| mixed | 三地址、RW/RO/W1C、位写掩码、两拍等待 | 582 笔访问、19 次复位、1164 个等待边沿、51 项覆盖 | 8 个全部拒绝 | 244.3 秒 |
| status | 两个不同地址、不同可写位、零等待 | 326 笔访问、19 次复位、34 项覆盖 | 5 个全部拒绝 | 170.2 秒 |

[完整功能证据](../../experiments/task-space-v1/register-family-v1/manifest.json)保存契约、义务、来源、实际判定和成本。17 个对照分别编译，没有跨候选构建复用。第二份没有 W1C、RO 或等待行为，因此不要求检出这些不适用的错误；仍需要验证地址归属、字节使能、复位、未映射响应和保留位。

一个开发版检查器曾把 SystemVerilog 保留字 `bins` 用作变量名，导致可信测试台编译失败并返回 null。改名后，同一合法 RTL 完成正例验证，原 null 和来源保持不变。后续篡改副本中的实际输入、候选源码和结果均被审计器拒绝；这些一致性挑战不等于证明功能判据已经完备。

在合法本地 EDA 环境中，配置文件只指定 `eda_env_script` 和 `apb_vip_root`，分别是统一环境入口与已生成的 APB VIP 包。随后可在项目 checkout 运行：

```bash
python3 -m environment.register_instance_controls candidate \
  .local/register-controls .local/register-config.json --max-seconds 1800
```

执行器拒绝覆盖已有结果，任一合法实现失败或负例仅因编译、超时、环境故障而停止，都会中止该银行。返回的 `controls_passed` 只表示实例功能层结果，`admitted` 仍为 false。独立采样还需要具体任务环境的权限、预算、提交与反馈隔离验收，不能直接借用单事务路由族的凭据。
