# 退休信用与队列任务族 v1

一个请求被接收、在 APB 上执行完成、最终被 AXI 请求方消费，是三个不同事件。本任务族将它们之间的关系作为契约：未退休名额直到 B/R 握手才释放，执行器在该响应消费前仍保持占用。它复用 Task003 的协议和仲裁规则，不改变原任务，也不叠加 Task004 的响应解耦。

三个候选分别保留每方向一个名额、每方向三个名额、写一个与读三个名额。一个名额仍允许读写独立接收和不完整写请求，因此不同于 Task001 的全局单事务。三个名额引入非二次幂存储回绕；不对称配置可将读缓冲与写缓冲的设计要求分开。它们是同一能力族的参数化契约，不是三个新协议，也尚不是经验难度排序。

## 从契约派生验证义务

[contracts.json](contracts.json)限定可接受组合；[anchors.json](anchors.json)另行记录经审阅的容量事实。生成器输出 `obligations.json`，连接容量参数、实际激励、独立判据、必要覆盖和错误对照。

例如，容量三要求在一个复位区间内反复接受、执行和退休超过三个容量长度的不同地址请求。测试不能只证明第三笔曾经入队：独立 UVM Scoreboard 还要核对每笔 APB 地址、数据和响应顺序，才能发现索引进入不存在的第四个槽。覆盖记录表示实际观察到的接口行为，不声称直接看到了 DUT 内部指针。

两个合法参考分别采用环形索引与移动数组。后者支持同周期退休与新请求接收，前者允许保守地到下一周期再使用释放容量；两者均是合法实现。错误对照包含越容量、提前释放信用、回绕、同时移位与插入、配对、仲裁、背压、复位、字节使能和错误响应等明确违例。某项变体不适用于当前容量时，不伪造它为有效负例。

另一个账本只从 AW/W/AR 与 B/R 引脚握手更新计数，与 Scoreboard 的队列长度比较。两者不一致时属于可信验证器错误，返回不可判定；候选超容量而两账本一致时仍按功能/时序错误判罚。独立账本、控制样本和有限覆盖不构成完整形式证明。

## 生成与运行

```bash
python3 task_families/queue_v1/generate.py x2p_queue_three_v1 .local/queue-three
python3 scripts/tasks.py --package .local/queue-three list
python3 scripts/tasks.py --package .local/queue-three reset x2p_queue_three_v1 .local/work
```

产物包含 Spec、初始 RTL、正反对照、VIP/UVM 后端、场景、运行时环境和接口。生成阶段先跑包内运行时单元检查；通过生成不代表已准入。配置与商业工具需要另行提供，`PB_CONFIG` 应指向可信执行配置。仅对自己生成并信任的源码包使用 `--package`；哈希检查不是任意外来代码的安全执行服务。

在配置好的可信 Linux 执行端运行 `python3 scripts/tasks.py quality TASK .local/gate`。对应的控制端使用同一包和门禁证据，通过 `rollout TASK -- --admission GATE ...` 启动。`test`、`submit` 与旧接口一致，相对路径按包为工作目录解释。

## 有限复用与观察版本

包仅保留执行组件和历史基线核查必要证据，不复制整个研究文档、图形及其他历史试次。任务门禁仍绑定完整执行源码范围；未缩减验证判据或沿用失效准入。原路由生成器与历史包不回改。当前没有通用插件加载器或跨契约二进制复用。

新包中的 `runtime-events-v2` 提供真实事件窗口：例如 `{"tool":"observe","start":"B:0","count":8}` 表示查询首个 B 退休附近的八周期。成功实验默认选择首个有效事务事件，失败仍围绕首错定位；不存在或未捕获的事件明确返回 NOT_CAPTURED，不猜测波形。查询只读取最近一次公开实验的固定接口采样，不访问 DUT 内部、私有测试或任意文件。调用预算保持 20 动作、2 次公开测试、3 次实验、4 次查询，终局验证不加载实验观测副本。

新版本还说明激励延迟的具体参照事件，并在包内提供 v4 交换导出，保留事件选择动作与实际观察、将保留评估单独分区。实际工业验收和模型数据应另以对应来源哈希发布；本页说明实现，不以源码或单元通过代替真实仿真。
