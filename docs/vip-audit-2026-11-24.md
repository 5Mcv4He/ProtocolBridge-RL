# R-2020.12 VIP 本地分发资源与能力审计摘要

**审计日期：2026-11-24**  
**基线**：[50 包资源盘点](vip-inventory-r2020.12.md)  
**研究状态**：资源分发文件盘点完成；5 个重点包已完成有限的本地文档能力核查；**尚无任何包通过完整运行与负例验收**。

> **证据来源和限制**：本文根据项目维护者提供的、已脱敏的本地 Agent 审计摘要整理；仓库维护者尚未在此公开仓库复验原始文件、文档或仿真日志。因此下列“本地确认”表示审计报告所声称的证据等级，而非本仓库独立复测。本文不包含专有 VIP 源码、内部文档正文、安装路径、许可证配置或原始日志。涉及受限能力元数据的公开范围仍应由授权持有人核实。

## 3. 当前运行证据的等级

本轮**没有执行商业安装器或仿真器**。审计仅复查过往 UTM / Zcode 运行记录的摘要：

- 部分 `NO_TB` / `NO_EXAMPLE` 来源于示例选择器没有匹配到项目，**不能证明 VIP 不可用**。
- 原有 PASS 判据主要依赖运行结束标志和 UVM error/fatal 为零，没有同时保证事务计数、预期数据正确与负例被检出。
- **I²C** 存在历史正例迹象：结束标记、零 UVM error/fatal，以及事务 trace 文件引用；尚未核查事务载荷与数量，也没有明确违规检测证据，因此状态是**历史正例线索**而不是 Smoke PASS。
- **AMBA** 在审计末次快照中新增 Zcode 批处理 PASS 报告；具体子协议示例、退出码、实际事务数和故意违规负例均未核实，因此状态是**批处理报告通过，待核验**。
- **截至本摘要，没有任何一个包满足**“成功编译、完整运行、存在真实事务、Checker 已启用，并能区分正常与违规”的完整验收标准。

## 4. 对任务工厂的初步影响

这一轮审计提供了优先研究的**候选方向**，并未认证任何训练任务可用：

| 候选任务关系 | 依据与约束 | 需新建或核查的独立检查 |
| --- | --- | --- |
| **AXI4-Lite → APB3/4** | AMBA 文档中已有相关端协议与事务监测接口 | 地址、数据、字节使能、响应及事务顺序映射的 Reference Model / Scoreboard |
| **APB 控制的 SPI / UART / I²C 控制器** | AMBA 和各外设接口存在监测/检查的文档能力 | APB 寄存器语义、命令状态、数据通路、异常与完成条件 |
| **TL-UL → AXI4-Lite** | TileLink TL-UL 文档与 AMBA 相关能力 | source/ID、mask、错误响应、先后顺序、未完成事务规则 |
| **SPI ↔ I²C 消息网关** | 两侧协议均有文档能力，**但没有天然唯一映射** | 必须新增完整的应用层消息格式、命令语义、重试及错误策略 |

**不要**把“VIP 提供所有 sequence”当作“所有 sequence 都应在某个桥接任务执行”。每个 Task 必须锁定适用的协议子集、规格与验证计划。

## 5. 下一个可验证里程碑

建议将现有历史记录视为线索，在合法授权与隔离环境中优先完成以下验证：

1. 固定一个已出现历史成功迹象的 **I²C** 示例版本、退出码、Seed、事务数量、检查配置，核验成功结果是有效事务而非空跑。
2. 加入一个可控制、明确的**协议违规负例**，确认 Checker/Assertion 已启用、会报告相应错误，并能将其与工具/环境故障区分。
3. 在真实桥接任务准备就绪后，增加一个**两端协议都合法、但事务映射错误**的故障变体；证明端到端 Scoreboard 能检出而两侧协议 Checker 不一定能检出。
4. 分别登记开发可见测试与终局独立验证的边界，记录相同候选在固定版本、固定 Seed 的可重放性。

> 每个 `PASS` 必须具备可核查的编译/仿真退出状态、非零且匹配预期的实际执行事务、检查开启证据、显式结束标记及适用负例。基础设施错误应单独标记，不能计算为 RTL 失败。

## 6. 结论与后续证据规范

本地清点支持 **50/50 分发包存在且标准数据段可读取**，并为 AMBA、TileLink、SPI、I²C、UART 建立了文档级的初步能力入口。但**尚未构成一个经独立执行验证的工业 VIP 后端**，也尚未证明任务生成、Oracle、Reward 或 RL 接口可用。

后续更新优先接收不包含商业代码的机器可读能力矩阵与脱敏执行摘要。未知字段保持空白；`confirmed_from_local_docs`、`reported_batch_pass`、`confirmed_by_execution` 不可互相替代。
