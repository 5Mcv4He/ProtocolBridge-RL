# 按事务事件寻找调试窗口

一次实验 PASS，并不意味着返回的波形窗口就有帮助。历史 Task003 的真实修复试次中，Agent 构造了单笔写实验，但默认窗口落在事务结束后的空闲区；后续按周期查询又只看到了复位。模型得到了数据，却没有看到它想解释的行为。

`runtime-events-v2` 改进的是**观测位置**，不是增加评分信息或把诊断改写得更长。它在新生成的队列包中独立版本化，沿用公开实验的真实接口采样，并保留原 `runtime-observe-v1` 的历史实现和轨迹。根目录旧 Task003 执行入口不会自动升级到这个版本。

## 从一个问题开始查询

假设要判断“外设完成写入后，响应被阻塞的期间是否错误释放了容量”。先运行一个具有等待或响应背压的公开实验，再寻找 APB 完成与 B 响应退休之间的行为。下列动作逐次提交，不是一次输出多个动作：

```json
{"tool":"experiment","scenario":"write_fifo"}
{"tool":"observe","start":"APB_COMPLETE:0","count":12}
{"tool":"observe","start":"B:0","count":8}
```

`APB_COMPLETE:0` 表示捕获记录中第一个 APB 完成事件；序号从 0 开始。窗口从该事件前两周期开始，最多十二周期。`B:0` 是第一次 BVALID/BREADY 握手，即写响应退休，不只是 BVALID 出现。读方向对应 `R:0`。

窗口仍显示固定的 AXI/APB 接口信号、实际握手事件与外部统计的未退休 AW/W/AR 数量。边沿前采样用于判定本次握手；边沿后采样用于观察状态更新，不能把同一事件再计一次。X/Z 用空值表示。它没有读取候选内部 FIFO 指针，也没有暴露私有场景。

| 查询方式 | 返回窗口 |
| --- | --- |
| `experiment` 失败后的默认反馈 | 首个已捕获错误附近 |
| `experiment` 成功后的默认反馈 | 首个实际事务事件附近，避免空闲尾部 |
| `observe` 的整数 `start` | 指定周期开始，兼容原查询方式 |
| `AW/W/AR/APB_SETUP/APB_COMPLETE/B/R:N` | 第 N 次相应事件附近 |
| 事件不存在或超过捕获范围 | `NOT_CAPTURED`、匹配次数与空行集合，不编造波形 |

`window` 字段说明选择原因、起点及锚点周期；`event_counts` 汇总已捕获的边沿前事件次数。缺少事件不能直接推断 DUT 永远不会产生它：记录可能被首错终止或捕获上限截断。`capture_limit_cycles` 与 `truncated` 仍保留供判断。

## 自定义事务中的延迟从哪里算

`experiment` 可以提供 1–16 行结构化事务，而不是可执行 SystemVerilog Testbench。每行格式为：

```text
[write, address, data, strobe, address_delay, data_delay,
 APB_wait, response_stall, error, start_delay]
```

这些变量不是全部相对于“仿真第零周期”。`start_delay` 从批次启动计时；通常地址延迟参照前一个地址握手，W-before-AW 模式的首个地址则参照 WVALID；数据延迟通常参照本笔写地址有效，W-before-AW 模式参照前一个 W 握手。APB 等待作用于目标 Access 阶段，响应停顿参照 BVALID/RVALID。它们沿用已验证的 VIP 激励方式，在新 Prompt 中明确写出，避免模型错误地按绝对时间推理。

实验应服务于具体假设。例如要观察名额是否保留到退休，应安排足够请求填满容量并延长响应背压，而不是仅运行一笔无竞争写入后就推断队列正确。当前自定义行不支持任意复位控制；复位使用已声明的公开命名场景。

## 权限与预算没有变成开放终端

此配置仍为 20 次总动作、2 次完整公开测试，另允许最多 3 次实验和 4 次观测查询；它们共享总动作预算。只能查看最近实验，反馈绑定当时的 RTL 哈希，编辑后旧结果不会自动成为新代码的证据。拒绝的参数或越预算请求不启动仿真。

求解进程不能读参考实现、私有输入和可信评分器，也不能选择任意文件、信号或 shell 命令。`submit` 冻结并停止求解，独立终局验证不加载观测实验副本。实验 PASS 不能替代 Reward。

这个配置还保留原实验 Prompt 的“先测试起始候选”提示。因此将它与基础 E 比较时，除了工具集合，还存在流程提示差异；应作为**工具配置组合的探索**，不能把小样本结果归因于事件导航一项。编译、综合、诊断和实验全部合并的综合环境尚未在此版本实现。

## 怎样核查实际可见信息

[窗口投影源码](../environment/runtime_navigation.py)只从已有公开记录选取白名单内容。生成包中的实际 Session、Prompt、审计器与 v4 交换导出同步绑定新版本；交换数据保存模型动作及真正返回的观察，将保留评估单列。

验收分三层理解：历史记录重放可以证明窗口选择变化；真实工具正反对照可以证明仿真和权限机制正常；只有真实模型轨迹才能回答 Agent 是否使用这些信息修复了问题。这三层不能互相替代。实现机制见[队列任务族](queue-family-production.md)，实际工具验收与模型行为见[研究报告](queue-family-evaluation.md)，原版本接口见[运行时实验](runtime-experiments.md)。
