## 真实失败与修复行为

- `r01-test_diagnostic`、`r03-test_verdict`：one-hot选择值001/010/100直接用作`pready[tgt]`、`pslverr[tgt]`及读数据切片索引。目标0错误读lane1，目标2索引4越界。实际先被BRESP事务比对检出；C在两次FAIL后仍保留此错误。
- `r02-spec_only`：`s_awready`同时由连续赋值和`always_comb`驱动，VCS报ICPSD编译错误。不能把它描述成已经完成的功能仿真失败。
- `r01-test_verdict`：第一次候选完成后仍保持PSEL，造成虚假Setup及VIP时序错误，同时存在错误PREADY选择。第一次修改修复这些问题，但未映射响应仍留在IDLE，无法正常清除VALID；第二次FAIL后进入RESP处理，最终私有与保留都通过。这里只证明反馈后有对应修改，不把模型内部推理或策略因果优势当作已测事实。

## 已验证范围与下一步
