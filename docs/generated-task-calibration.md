# 自动生成的任务能否进入真实求解闭环？

生成 Spec 和 RTL 模板只完成了任务生产的一部分。研究者还需要确认：**新契约有独立的正确性判据，运行器确实使用该版本，模型获得的反馈与它当时提交的源码一致。** 本页记录两份生成路由任务经过当前准入后，由同一个模型独立求解的实际结果。

两条新试次均完成原生工具交互、提交、独立评分和轨迹审计：一条失败，一条在收到公开失败反馈后修改并通过。它们是不同地址契约各一次求解，**不构成反馈策略对照，也不足以估计稳定成功率**。另有一条较早试次因可信结果分类问题停止，原始 `reward=null` 单独保留。

## 从契约到求解，中间有哪些判断？

这里的任务仍是 AXI4-Lite 到三个 APB4 目标的协议桥。Agent 要实现地址归属、目标局部地址转换、独立写地址/数据接受、等待、错误、背压与复位。不同契约改变地址窗口；它们没有因此变成多个不同的协议能力。

系统分别核对三个层次：

1. **生成一致性。** Spec、接口、参考结构、场景、错误对照和来源清单是否来自同一份契约。
2. **实例功能。** 在实际 VCS/VIP/UVM 环境中，两种合法实现通过完整与公开测试，适用功能错误对照被拒绝。VIP 检查单端协议；独立 Scoreboard 和引脚账本检查转换与响应归属。
3. **可运行环境。** 运行器、权限、预算、反馈投影、输入集合与实例证据严格绑定。只有匹配的任务才能进入当前采样池；历史通过结果不能直接授权修改过的验证器。

原生工具适配器的资格验证包含 38 次实际 SDK 工具调用，另有 14 项实际任务环境检查。它们验证工具边界，**不是 38 条模型试次**。本次实际求解沿用 `read/edit/test/submit`；没有将已有九动作综合环境混入这个条件。

## 事先固定的条件与结果

两份任务均从接口模板开始，使用 `deepseek-flash`、reasoning off、DSH SDK/Runtime `0.2.2rc2`、原生接口 v3 与 transport v5。每条最多 20 个动作、20 个模型请求和 2 次公开测试。温度使用服务默认值，未固定采样种子，精确权重版本不可取得。公开、终局和保留输入分别冻结；提交结束求解后才执行两个独立评分。

实际仿真为 VCS `O-2018.09-SP2`、AMBA VIP `R-2020.12`、**UVM `1.1d.Synopsys`**。本次观测值不能用较早部署说明中的 UVM 1.2 代替。研究源码记录基于 `b7788d6` 加冻结的新增文件，各文件哈希见汇总，未声称运行来自一个没有未提交修改的提交版本。

| 实际观察 | 地址契约 A | 地址契约 E |
| --- | ---: | ---: |
| 独立试次 / 有效提交 | 1 / 1 | 1 / 1 |
| 执行动作 / 编辑 / 公开测试 | 9 / 3 / 2 | 7 / 2 / 2 |
| 动作格式拒绝 | 0 | 0 |
| 最终源码的公开验证状态 | 未测试 | PASS，22 case |

失败运行按首个错误结束，不能把尚未执行的 case 计为通过。保留评估单独报告，没有合成第二个训练奖励，也没有用于替模型挑选中间版本。

反馈实际只含状态、错误类别、当前源码哈希与剩余额度。以下 case 名和引脚诊断来自可信侧的**离线研究分析**，不是模型当时看见的详细诊断。

## 一条轨迹出现了可核查的局部回归

A 的首个编辑候选通过 `address_data` 等前十个公开 case，在 `reset_w_only` 失败：复位后的独立写数据接受未满足规定期限。第二个候选在**完全相同的 `address_data` 输入**上提前返回 AXI 响应，APB 尚未完成。源码哈希和实际输入匹配支持“这个 case 发生回归”，但不能据此称第一版整体正确。

模型随后又编辑了一次，耗尽的公开测试额度没有覆盖最终版本，便提交了它。终局验证再次发现提前响应。最终源码中存在一个可解释该现象的关系：同时接受 AW/W 时，目标译码仍读取旧的 `aw_addr`；虽然另有 `wr_addr` 表达当前请求地址，它没有参与译码。对旧地址的判断可能把映射内请求当成未映射请求，直接产生错误响应。

这段源码分析解释了实际失败机制；它不证明模型内部如何推理，也不能证明增加预算一定能修好。我们没有给未测试版本补做候选排名，或利用保留结果回选较好版本。

核查：[行为审计](../experiments/task-space-v1/calibration-v2/task-a-behavior.json)、[最终源码](../experiments/task-space-v1/calibration-v2/exchange-v10/artifacts/759fe2b44d9eec444d1ec69b8fa353de536873ab8d220a21f44d589dbbef5388.sv)。

## 另一条轨迹在失败反馈后形成有效实现

E 的首个候选没有驱动 APB 的保护属性信号 `PPROT`，工业协议检查实际检测到未知值。模型收到了 `FAIL / protocol_timing_error`，随后修改并再次测试。新版公开 22 case 通过，模型提交同一源码，终局与保留集合各 27 case 通过。

新版包含 `assign pprot = 3'b000`，同时改变了其他逻辑。因此可以确认“失败反馈送达后发生编辑，随后同一提交通过完整验证”，不能把全部改善归因于这一行，也不能声称模型从受控反馈中准确定位了那条私有诊断。

核查：[行为审计](../experiments/task-space-v1/calibration-v2/task-e-behavior.json)、[最终源码](../experiments/task-space-v1/calibration-v2/exchange-v10/artifacts/dec5ea49b4085daece1284eaa992cc8c448cfdeac4dce45fc1f0db060a79d9d2.sv)。

## 较早的 null 为什么不改写成失败？

[原始导出与后续中断审计](../experiments/task-space-v1/interrupted-v1/summary.json)分别保存，未修改历史状态。

较早版本启动了一条真实试次，产生 5 个有效工具动作、2 次编辑、1 次公开测试和 17,759 Token。候选把 BVALID 与 RVALID 连接到同一个响应状态，因此写事务也发出没有读请求的 R 响应。VIP 发现问题，但可信汇总没有可靠分类，返回 `public_environment_error`；预声明停止规则终止该批，模型未提交，计划中的第二条没有启动。

研究随后增加独立的请求接受/响应归属账本，在**完全相同的候选源码**上复验，实际得到协议/时序拒绝。新版本还通过了两种合法结构各 27 个完整及 22 个公开 case，16 个针对性错误对照被拒绝。这是单独的验证器质量调查。原始试次仍为 null，新模型批次另行冻结，不能回填历史奖励或将两个版本合成成功率。

## 数据能够支持什么用途？

[v10 交换集合](../experiments/task-space-v1/calibration-v2/exchange-v10/manifest.json)分别保存模型产生的原生调用、控制器实际执行的操作和实际送达反馈。最后一次 submit 的结果不需要再触发下一次模型请求；审计因此区分“工具已返回”和“后续模型请求已包含该观察”。

训练侧目录保存真实交互与终局奖励，evaluation 目录单独保存保留评估，analysis 目录说明没有事后重评分候选。成功与失败都保留，导出并不意味着已证明训练收益。Token IDs、行为 log probability 与精确权重版本不可用，不能当作完整的 on-policy 优化器输入。

新的[候选行为分析器](../scripts/package_behavior.py)核对实际源码、公开输入与反馈身份，可以用于研究修改、复验、回归和最终选择。它不读取保留结果来筛选训练记录，也不自动推断未测试候选的正确性。

## 成本与下一步选择

两个新试次共报告 93,888 Token，耗时约 24.1 分钟。SDK step 计时分别为 23.546 和 15.734 秒，它不是独立测量的服务端推理延迟。实际 EDA 每次公开、终局和保留评分分别编译；[行为记录](../experiments/task-space-v1/calibration-v2/task-e-behavior.json)提供 VCS 报告的编译/仿真 CPU 时间和外围评分墙钟时间。没有可靠 API 货币费用，未把 CPU 时间冒充编译墙钟时间。

当前证据支持将**生成包、源码匹配准入、真实原生交互、候选演变与独立奖励**连接成可审计闭环；尚不支持稳定成功率、反馈因果收益或训练收益。生产侧优先继续验收具有不同地址边界与生命周期组合的候选；数据侧下一步更值得保留跨版本的实际测试状态和错误机制，选择新的工程差异进行少量校准，而不是为当前一胜一负追加样本直到结果好看。


## 独立的字对齐实例：验证后提交，不是失败后修复

第二轮生产按事前成本与边界覆盖规则选出三份工业实例，随后在首次模型请求前固定其中第一份 N，另行声明只运行一次。没有从模型结果中挑选起点，也没有追加替代样本。模型仍为 deepseek-flash，原生动作、20 次总动作和 2 次公开测试上限不变；任务契约与输入属于新的独立批次，不能直接混入上述两条的成功率。

这次实际使用 6 个动作：读取规格与 RTL、编辑两次、测试一次、提交。第一个编辑没有测试，第二个编辑通过 22 个公开 case，PASS 确实进入后续模型请求，模型提交同一源码。停止求解后，终局与独立保留各 27 case 通过。它支持“生成任务池可对新契约执行完整求解与独立评分”的结论；没有失败反馈或事后首候选测量，因此不支持“通过反馈修复”或“第一份候选就正确”的结论。

这条试次消耗 24,131 Token，整体约 778.9 秒。公开与终局各独立编译，报告的编译 CPU 时间分别为 90.885、87.500 秒，仿真 CPU 时间分别为 16.53、44.80 秒；保留评估成本另放 evaluation。没有可靠货币费用或服务端推理延迟测量。

核查：[冻结条件与结果摘要](../experiments/task-space-v1/calibration-word-v1/summary.json)、[实际候选与反馈关系](../experiments/task-space-v1/calibration-word-v1/behavior.json)、[独立交换清单](../experiments/task-space-v1/calibration-word-v1/exchange-v10/manifest.json)。这一成功样本使任务执行覆盖更广，但不足以证明难度饱和或自动生产提高了训练收益。
