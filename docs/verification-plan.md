# 001 验证计划：从 Spec 到 case 与证据

状态：v3 参考完整回归与 10 个错误对照已实际验证；真实 Agent 试次进行中。具体结果以评估报告为准。

当前桥只允许一笔未完成事务。充分验证的目标是覆盖这个 Spec 内的功能和边界，不能通过扩大不支持的协议范围来增加表面测试量。UVM sequence 负责生成／发送事务；case 定义一次场景；test 组装环境；campaign 执行 case 集合；Scoreboard 与断言判定结果。

## 功能点与 case

| Spec 要求／边界 | 定向 case | 主要判据 |
|---|---|---|
| 32-bit 地址原样转换，含高位与边界地址 | address_data | AXI 计划、APB Monitor 地址逐笔一致 |
| 全零／全一／交替／walking-one 数据 | address_data | 数据和独立内存比较 |
| 未写地址读取、连续读 | read_only | 预期初始化数据、无额外 APB 写 |
| 连续写、部分写累积、零字节使能 | write_accumulate | 独立预期内存与实际目标内存 |
| 16 种 WSTRB，含正常与错误写 | strobe_cross | 数据／字节使能／无错误写副作用 |
| AW 先到、W 先到、同周期，间隔 1/2/15/16/31/64 | channel_gaps | 两半请求只接受一次、未齐前不执行 |
| APB 等待 0/1/2/7/16/64 周期 | wait_error | Setup/Access、稳定性和完成采样 |
| PSLVERR 对读写响应的映射，错误读数据 | wait_error | BRESP/RRESP/RDATA 比较 |
| B/R 背压 0/1/2/15/16/31/64 周期 | response_backpressure | VALID 与 payload 稳定、无重复事务 |
| 读写方向切换、重复地址、随机间隔 | mixed_stream | 持续状态与事务数量一致 |
| 仅 AW 已接受时复位 | reset_aw_only | 丢弃半请求，复位后恢复 |
| 仅 W 已接受时复位 | reset_w_only | 丢弃半请求，复位后恢复 |
| 写／读 Setup 中复位 | reset_write_setup / reset_read_setup | 终止未完成 APB、清空请求 |
| 写／读 Access 等待中复位 | reset_write_wait / reset_read_wait | 无虚假完成，复位后恢复 |
| BVALID/RVALID 被背压时复位 | reset_b_stall / reset_r_stall | 丢弃 AXI 响应；已完成的 APB 副作用不回滚 |
| PPROT=0、读 PSTRB=0、禁止提前响应、各阶段 16 周期进展要求 | 全部 case 的引脚断言 | 协议／任务时序错误直接失败 |

随机测试另包含四条由独立种子派生的 256 笔合法事务流；等待、错误、背压、字节使能和通道顺序独立抽样，边界值提高抽样权重。长阶段中的复位分别在进入阶段后的 0、1、7、31 周期触发；Setup 只有一周期，单独测试该位置。延迟基线分别统计请求接受到 Setup、APB 完成到 AXI VALID，以及外部等待与背压。

常规数据场景共用底层单事务 driver，复位场景增加中断／重启流程。创建更多类本身不代表更完整；验收依据是实际执行的 case、观察到的覆盖项和错误实现检出率。

## 交叉覆盖目标

最终 strobe_cross 与 strobe_cross_early 合计对以下组合做显式枚举：

```text
16 种 WSTRB × 3 种 AW/W 顺序 × 2 种错误响应
× 3 种等待类别（0、1～8、>8）× 2 种背压状态（无／有）
= 576 个必要交叉 bin
```

READY 的默认电平在每次仿真开始时固定，避免动态重配影响下一笔事务。early 模式在响应前就拉高 READY，实际背压为 0；reactive 模式等到观察 VALID 后按指定延迟拉高，实际阻塞采样周期数为延迟值 + 1。每笔都核对该关系。交叉覆盖的“无／有背压”依据实际引脚，不依据配置标签。

bin 使用实际 VALID 提供顺序、实际等待／背压计数和已检查事务采样。READY 何时接受由 DUT 合法实现决定，因此不会把“两个 VALID 同时提供”误写成“必须同周期握手”；握手顺序另作诊断统计。缺少必要 bin 的无错仿真属于验证不完整，不返回成功奖励。该目标是任务级覆盖计划，不等于整个 RTL 的代码覆盖率达到 100%，也不覆盖所有无限长时间组合。

## RL 的三层测试安排

| 层 | Agent 是否可调用 | 用途 |
|---|---|---|
| 公开开发测试 | 可反复调用，获得错误摘要 | 调试接口及代表性 Spec 场景 |
| 私有奖励测试 | 提交后由控制器调用，求解过程不可读取具体输入 | 产生该 episode 的终局奖励；若未来训练，奖励可用于学习 |
| 保留评估集 | 不作为逐轮调试或训练反馈 | 在模型／策略冻结后评估泛化，防止只拟合奖励测试 |

各层支持同一 Spec，隐藏的是具体样本和种子，不是偷偷增加功能要求。公开仓库可以发布场景类别和评估方法；私有具体输入放在求解进程无法访问的目录，记录哈希和版本。最终奖励集不应被误称为永远不参与学习的 holdout。

## 本轮验收顺序

1. 正确参考实现通过所有必要 case，检查复位中断的事务账目。
2. 六种既有错误实现继续被检出；增加保留半请求、复位未清响应、提前采样读数据和接受延迟超限四种错误对照。
3. 检查缺少场景／缺少覆盖、编译错误、超时和基础设施故障的分类。
4. 在 UTM 内实际运行 DSH，并验证其 UID、文件系统／进程隔离及 API 调用。
5. 冻结任务、验证器和私有输入，再运行真实 Agent，保留成功或失败的真实终局结果。
6. 更新架构、使用说明、验收报告和脱敏证据；在完成之前不把计划写成已实现。

## 随机 case 具体是什么

随机输入由 `scenarios.py` 的种子化生成器产生，UVM sequence 使用它们驱动商业 VIP。它不是由 Python 计算正确答案，也不是把随机日志当仿真。固定 seed 的向量可以保存和重放；VCS 内部随机 seed 固定为 17。

| 维度 | 四组 random_stream 的取值 |
|---|---|
| 长度 | 每组 256 笔，四个派生 seed，共 1024 笔 |
| 方向 | 随机读写，穿插连续读／连续写段 |
| 地址 | 75% 从 16 个重复地址取样，25% 从全 32-bit 对齐地址空间取样 |
| 数据、字节使能 | 32-bit 随机数据；16 种 WSTRB 随机取样 |
| AW/W 顺序 | 同时、AW 先、W 先随机选择 |
| 延迟／等待 | 重点取 0、1、2、15、16、31、32、63、64；通道分离取非零值 |
| 错误 | 每笔独立以 25% 概率请求 PSLVERR，与地址／等待／strobe 解耦 |
| 事务间隙 | 0、1、7 的带权取样，加上 driver 调度间隔 |

边界值来自当前验证预算，不意味着 Spec 只支持最长 64 周期。默认固定回归、私有奖励与保留评估分别记录输入哈希。私有奖励与保留评估使用独立生成的种子；同一试次运行途中不重新抽题。

## 怎样判断“足够”，还缺什么

不能用 16 个、22 个 case 或“随机跑过”来证明完备。当前验收门槛是：Spec 内每项行为有检查；计划场景实际命中；必要交叉 bin 齐全；事务账目完整；错误对照被检出；真实提交由冻结的独立验证器评分。

当前仍有这些具体边界：

- 随机流数量有限，未穷举所有数据、地址和无限等待长度。
- 复位覆盖八种阶段与多个偏移，但未对所有 strobe／错误／等待／复位宽度做笛卡尔积，也未覆盖每种复位与完成同拍的情况，以及不跨时钟有效沿的窄复位脉冲。
- 有请求接受、APB 启动、响应产生的进展上限和延迟统计；无最大吞吐率、面积、频率或功耗验收。driver 有调度间隔，不能用整场仿真平均速率代表桥的最大吞吐率。
- 当前 576-bin 目标是可审计的功能覆盖子集；没有 RTL line/branch/toggle/FSM 覆盖闭合，也没有所有商业 VIP covergroup 的闭合报告。
- 手写故障对照仅证明对这些错误敏感，未做系统化 mutation campaign 或形式完备性证明。
- 不测试 Spec 明确不支持的并发读写、burst、非对齐地址或非法请求方行为。

这些缺口主要需要额外验证工程和运行预算。代码覆盖可继续核对现有 VCS 配置与许可；综合／形式工具需求单列于[工具说明](toolchain.md)，不把所有缺口都归因于缺软件。
