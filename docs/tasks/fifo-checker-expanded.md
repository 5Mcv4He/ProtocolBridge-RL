# 检查队列，而不是实现队列

Agent 交付的 `checker.sv` 接收请求接受与退休事件，判断它们是否符合有限 FIFO 的容量和身份规则。被提交的检查器本身是待测对象：可信侧另用独立事件队列模型给出正确判断，因此候选不能通过无条件通过或无条件报错获得奖励。

此前深度 2／3 已形成任务。本轮把生成域扩到深度 1／5，以检查参数变化是否带来新的验证义务，而不是仅多生成两个目录。

| 契约 | 有实际差异的边界 | 针对性验证 |
| --- | --- | --- |
| [深度 1](../../tasks/fifo_checker_d1_v1/spec.md) | 满槽同周期退休旧身份、接受新身份；空槽不能直接旁路退休 | 下一次必须退休新身份；删除在单槽下不构成错误的“指针未移动”负例 |
| [深度 5](../../tasks/fifo_checker_d5_v1/spec.md) | 容量不是二次幂；存储需要多轮回绕 | 拒绝模 8 回绕、把容量取整为 8、两位计数截断等错误 |

例如槽中有身份 A，同周期接受 B 并退休 A 是合法的。下一次退休应匹配 B，而不是继续匹配 A。这个时间关系要求检查器维护“事件之前的队头”与“更新后的状态”，仅检查某个身份值出现过是不够的。

[39 项工业门禁](../../experiments/task-production-v3/checker-quality-v3.json)包含两种合法结构、功能错误对照、无效接口和语法错误。功能负例须得到实际事件判断不一致，编译失败不能替代其检出证据。必要事件由独立模型生成并逐周期比较；有限测试仍不构成任意深度或任意序列的形式证明。

深度 5 已有一条真实模型修复：首候选按三位索引自然回绕而失败，修改为显式 4 → 0 后通过公开、终局及保留检查。深度 1 尚未模型采样；[阶段分析](../task-production-stage-v3.md)区分这一实际修复与稳定难度结论。

## 生成、准入与使用

```bash
python3 -m task_families.fifo_checker_v1.generate_v3 5 .local/checker-five
python3 -m verifier.fifo_checker.quality_v3 .local/checker-expanded-gate
```

[生成器修订 3](../../task_families/fifo_checker_v1/generate_v3.py)与[准入检查](../../task_families/fifo_checker_v1/qualification_v3.py)保持旧深度 2／3 的历史来源不变。新门禁仅支持新生成的深度 1／5；不能推断深度 4 已准入。模型求解必须使用匹配的运行配置和来源冻结，生成成功本身不是可运行资格。
