# 从一份新契约，到可运行的生成任务

任务生产的瓶颈不只是写出更多 Spec。改变地址窗口后，合法实现、错误对照、边界激励和最终评分都必须仍然解释同一件工程行为；改变运行器后，历史通过记录也不能直接证明新环境可以采样。本阶段把这些判断拆开，并通过两轮实际生产检验它们。

**已经完成的闭环是有限路由域的自动生产、实例工业验收、来源匹配准入和真实模型求解。** 两轮各生成 20 份新地址契约；第二轮预先选定的三份完成工业与运行准入。第一轮两份契约在修订后的验证器下重新准入，并完成一胜一负的模型试次。未验收的候选不进入可运行任务池，参数实例也不计作新的协议能力。

## 什么发生了工程变化？

对象仍是 32-bit AXI4-Lite 到三个 APB4 目标的单事务桥。第一轮采用页对齐窗口；第二轮允许四字节对齐、4–16384 字节长度的窗口，目标可以相邻、相隔一个字或靠近地址上界。改变的是“哪一个请求属于哪个目标，以及它在目标内部对应哪个地址”，不是测试随机种子。

例如，从全局地址 `0x100c` 开始、长度 4100 字节的窗口会跨过页边界。正确局部地址必须减去完整基址。截取地址低位、先去掉基址低位再相减，都会在特定位置访问错误的数据。因此生产器随契约装配边界、内部进位与地址别名检查，以及适用的错误对照。

协议角色和转换含义没有因此任意扩张。[空间分类器](../task_families/router_space.py)会分别说明：协议契约自相矛盾、角色尚未资格验证、位宽转换缺少独立判据、并发组合需要新义务，或当前生产域支持生成。分类结果不是工业准入。

第二轮的 24 个提案有 4 个被拒绝：现有地址别名负例需要一个未映射见证，但该位置被另一个合法窗口占用。它们不属于当前错误银行的适用域；这不代表那些电路工程上不可实现。生产域需要说明这种限制，不能为了增加数量让一个不再具有区分力的负例继续过门禁。

## 生成、验收与采样各自负责什么？

| 层次 | 实际判断 | 不代表什么 |
| --- | --- | --- |
| 契约与材料生产 | 合法窗口、完整 Spec/RTL/验证材料、依赖清单及静态检查 | 不证明真实工具可运行 |
| 实例功能对照 | 两种合法结构通过；适用错误实现被功能或时序检查拒绝 | 不证明运行权限与反馈边界 |
| 公共环境资格与来源匹配 | SDK 调用、权限、预算、提交、完整输入和实际文件身份一致 | 不给未来候选继承旧奖励 |
| 当前任务池 | 只列出严格匹配准入证据的任务包 | 不等于所有已生成或历史通过任务 |
| 模型求解与独立评分 | 新会话实际操作，提交同一源码后重新评分 | 不证明稳定难度或训练收益 |

公共机制资格可以在严格匹配的范围内复用；具体实例仍执行自己的功能对照。当前运行机制有 38 次实际 SDK 调用和 14 项实际任务环境检查，均与模型推理试次分开统计。[准入实现](../environment/package_admission_v3.py)核对实际依赖，[任务池](../environment/package_pool_v2.py)拒绝过时凭据。

参考与检查也不是同一套表达式互相认同：地址关系使用明确边界锚点，合法实现有不同结构，工业 VIP 检查协议，独立 Scoreboard 检查端到端事务，引脚账本另外核对请求接受和响应归属。这些方法降低共同错误风险，仍不构成形式完备性证明。

## 两轮生产留下了什么证据？

| 集合 | 第一轮页对齐域 | 第二轮字对齐域 |
| --- | ---: | ---: |
| 生成并静态通过的新契约 | 20 | 20（24 提案中 4 个先拒绝） |
| 当轮完成完整工业控制银行 | 5，随后因新发现的分类问题停止扩容 | 3，按事先选择全部完成 |
| 修订后当前源码匹配准入 | 2，另行重验 | 3 |
| 本页所依据的已完成模型试次 | 2；另有较早中断 1 条 | 1 条独立冻结试次，终局与保留分别通过 |

第一轮其余 15 份、第二轮其余 17 份没有工业完成证据。历史五份控制银行不会被改写成修订后已验收，较早模型试次的 null 也保持不变。第二轮材料化结果文件中的 `industrially_admitted=0` 描述生成结束时的状态；后续三份准入在独立证据中追加，不回填原始记录。

第二轮三份实例均执行两种合法实现各 27 个完整与 22 个公开 case，17 个错误对照实际被拒绝，每份审计 116 条仿真及对应输入记录。功能负例不能仅因编译失败、环境异常或不完整验证而被计为检出。真实 VCS 为 `O-2018.09-SP2`，AMBA VIP 为 `R-2020.12`，运行横幅所见 UVM 为 `1.1d.Synopsys`。

## 第一轮发现怎样影响第二轮？

较早真实候选把 BVALID 与 RVALID 连接到同一个响应状态。VIP 报告没有读请求却出现读响应，原汇总却无法可靠分类，返回 null。研究据此增加独立的接受/响应归属检查，用**同一候选源码**确认实际拒绝，再执行新版本正反对照和新的模型计划。原奖励没有被修正成 0。

第二轮的[选择器](../task_families/router_v6/select_v2.py)只接受已完成工业对照耗时、这个已确认的验证问题及契约特征，按有限成本选择边界差异。它不读取模型成功率或保留评估。费用估计用已观察最大成本加 10%；最终选择三份，在 3600 秒工作预算内实际完成。一个选择标签曾把“相隔一个字”误认成未映射间隙；检查第三个窗口的占用后，在工业执行前另行修订，旧记录保留。

这证明生产分布能使用实际质量和成本证据调整。它尚未证明自动选择了更有训练价值或更难的任务；这需要后续有计划的模型测量。

## 复用降低了哪些成本，还有什么没有解决？

| 第二轮实例 | 编译次数 / 复用次数 | 实际仿真 | 整项验收墙钟时间 | 编译 CPU / 仿真 CPU |
| --- | ---: | ---: | ---: | ---: |
| N | 1 / 20 | 116 | 722.8 秒 | 91.369 / 135.68 秒 |
| A | 1 / 20 | 116 | 692.8 秒 | 94.027 / 136.13 秒 |
| Q | 1 / 20 | 116 | 640.8 秒 | 90.456 / 137.62 秒 |

[成本分析器](../scripts/control_costs.py)从真实日志与来源绑定的完成结果读取这些数字。控制银行把固定的一组合法及错误设计编译到同一可信构建中，再分别选择实际执行；复用要求完整构建身份匹配。没有复用旧判定结果。CPU 时间不是墙钟时间，当前没有独立计量编译与仿真各自的传输等待时间。

第二轮 20 份材料生产约 72.2 秒，单包约 8.71 MB、1801 个执行来源文件。新实例不需要新增 Task ID 分支，但包内继承组件仍较多。[内容存储工具](../task_families/source_store.py)能在清单不变时合并同内容源文件；这减少存储，不证明工业运行更快。实例验收仍约十一至十二分钟，不能用生成速度推断百级工业准入成本。

当前依赖冻结偏保守，运行器及工具配置变化会使旧资格不再适用。继续缩小必要依赖边界需要真实回归和适用域证明，不能靠删减哈希清单延长旧凭据寿命。冻结材料中 bit12 负例说明写成“至少 8 KiB”，实际适用条件是窗口大于 4096 字节；该文字限制已在证据旁更正，原清单未修改，实际 Spec 与功能判据未改变。

## 下一步怎样扩大才有意义？

路由与队列组合已经完成[两份新契约的实际功能对照](../experiments/task-space-v1/composition/manifest.json)：每份两种合法结构各通过 44 个完整与 42 个公开 case，38 个负例全部被功能／时序检查拒绝。新增的三个目标 × 六个复位阶段义务，按真实事件记录 18 项交互，而不是合并两套覆盖声明。生成负例也曾因同周期赋值覆盖而未产生预期缺陷；[同一对照前后的定向验收](../task_families/composed_v2/README.md)保留了这个失败和修正。这两份还没有对应的 Agent 运行准入，不能直接计入五份路由任务池。

APB 主动 Master 已通过[独立角色验收](../experiments/task-space-v1/resources/apb-master-v2.json)：合法自建对象完成六笔事务及十二个等待边沿，三个错误对照被拒绝。它没有继承 X2P 中 APB 从端角色的结论。[寄存器任务族](../task_families/apb_register_v1/README.md)已经实现受限材料生产与本地评分入口，两份不同设备契约也已通过[实际实例对照](../experiments/task-space-v1/register-family-v1/manifest.json)：每份两种合法结构通过，分别拒绝八个和五个适用功能负例。它们复用同一生成器与评分入口，共耗时约 414.5 秒，没有为实例新增任务专用控制代码；后续又完成独立运行准入，其中 mixed 契约的一条真实模型试次首编辑通过并原样提交，详见[寄存器运行闭环](register-family-runtime.md)。这分别建立了资源角色、设备语义、执行机制与实际求解证据，没有把材料生成等同于准入。

数据侧已有的[两条新生成任务轨迹](generated-task-calibration.md)表明运行闭环可用，也出现公开版本回归、未测最终提交和失败后有效修改。随后对预先选定的新字对齐契约另行冻结了一条试次：两次编辑、一次公开 PASS 后提交，终局与保留各 27 case 通过，消耗 24,131 Token。首个编辑未测试，不把它描述成首次修改成功或失败后修复；[独立记录](../experiments/task-space-v1/calibration-word-v1/summary.json)与先前两条保持分组。样本太小，无法据此决定所有地址参数的难度。新角色对应设备语义的正反对照与运行闭环现已分别完成；下一步优先补齐组合任务的运行准入，再根据实际复杂度与成本选择扩张范围。
